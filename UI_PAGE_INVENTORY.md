# UI Page Inventory

## Scope and method

This inventory covers the user-facing React interfaces under `apps/web/src`, `apps/admin/src`, and the shared product UI in `packages/storefront-ui`. It is based on route declarations, component trees, feature modules, styles, and local-preview review. Responsive review remains partial: the home page, admin overview and blog index were checked at all seven requested widths; marketplace, quote request, material list, contact and account templates were checked at 320, 375, 768, 1024, 1280, 1440 and 1920 px for page-level overflow. A 375 px article detail, admin audit view, and Staff & Roles view were visually reviewed; the customer list was reviewed at 320 px, the customer dashboard at 320 and 375 px, and the supplier form at 375 px. The account quotations activity and status-filter groups were also visually reviewed at 320 and 375 px; both now use balanced two-column controls with aligned count badges and no page-level horizontal overflow. The Staff & Roles create form was opened and reviewed at 375 px: its fields stack, and Cancel precedes the full-width create action at the form footer. At 768 px the overview KPI cards initially formed a three-plus-one grid; this was corrected to two columns at tablet widths and a single column on narrow phones. On the supplier form, the category picker label now wraps instead of truncating on mobile. The sales RFQ cards and filter group have also been visually reviewed at phone and tablet widths; the filters now use intentional grids at narrow widths and align in one row at 768 px. The customer dashboard’s orphan third KPI now spans the available row width and aligns its value at the far edge. Responsive review now includes composition and visual balance, not only overflow checks. This does not certify every route or state.

All 14 top-level admin workspaces were also checked at all seven viewport widths for document-level horizontal overflow; none was found. The supplier-create form was visually reviewed at 320 px. The supplier list was also visually reviewed at desktop: the status menu sits directly under its field, and selecting Suspended immediately shows a no-match state; Reset filters restores the full list. The Audit Log filter fields were visually checked at desktop and 375 px, with centered values and compact chevron placement; the storefront marketplace filters were also checked at desktop and 375 px. Nested admin views, dialogs and individual data states still require targeted review.

The storefront uses `AppShell` with a shared header, page area, footer, and conditional floating action dock. On phone widths, the dock keeps a single floating WhatsApp shortcut; the material list remains in the mobile menu. The shared mobile navigation button exposes expanded state and controls the link panel; live 320 px interaction review confirmed the links appear, Escape closes the menu, and focus returns to the toggle. The admin uses `AdminWorkspaceLayout`, a persistent sidebar, page header with a breadcrumb for the selected navigation group, global search on Overview, and a mobile menu. At 320 px the admin menu links and selected state are visible; Escape closes the menu and focus returns to its toggle. Nested Business and Sales navigation marks its current page semantically. Admin unselected navigation uses a subtle dark hover surface without horizontal motion; the selected item remains brand-orange with white labels and icons. Customer account pages have a dedicated shell and mobile navigation. Route and nested-view state are preserved in URL parameters in several workspaces. A follow-up source pass over all filter controls and submit forms found no additional Apply/Filter step: remaining Search buttons submit distinct customer/follow-up or supplier-directory queries, and standalone reset/clear/export actions do separate jobs.

The approved brand direction uses logo orange `rgb(234, 88, 12)` (`#ea580c`), deep navy `#0f172a`, white, and slate neutrals. Every orange-filled control in storefront, customer account and admin uses white text and icons; hover changes to `#c2410c` and keeps white labels. This applies to search and quote buttons, material-list actions, active tabs, filter chips, admin workflow tabs and preview toggles. Orange text links on white/pale surfaces remain dark orange for readability. The desktop header shows “Delhi NCR:” with the six service regions and a clickable phone number; responsive header layout keeps the Delhi NCR label and clickable phone number while hiding the region list through the compact-header breakpoint at 1120 px. Footer contacts and WhatsApp controls use the approved public contact details. The homepage hero surface, text and surrounding sections use the brand palette; its canvas animation and the direction map’s visual design and animations remain unchanged. Map route visibility follows configured service regions, even when the exact office address is blank.

Blue and purple UI accents in storefront and admin now use the approved orange palette, including informational accents, selected workflow/status treatments, active navigation, native checkbox/radio/range/progress accents, and text selection. Active admin/customer navigation uses orange with white labels and icons. Admin purchase-order PDFs use a pale-orange information surface, and delivery challan PDFs use an orange heading accent. The latest application-wide source scan found no saturated blue interface accents or blue-named utility classes outside the protected direction map. Navy/slate neutrals and semantic success/warning/danger treatments remain intact. Supplier and partner logo artwork retains its original colors, text, and design; the orange palette applies to interface controls and accents only. The direction-map palette and animation/design remain unchanged.

## Admin and internal workspace

The admin application is a single protected workspace, with login shown before the authenticated layout. Top-level tab selection is stored in `?workspace=`. Most feature areas combine list, detail, create/edit, and confirmation states inside a tab rather than using separate routes. Live heading review across all 14 top-level workspaces found one page-level `h1` in each. A populated customer-history detail also renders one `h1` for Customers, its customer title as `h2`, history groups as `h3`, and individual request/quotation records as `h4`; remaining detail, edit and confirmation headings remain under review. Loaded empty states are part of the shared interaction audit; several dashboard and list empty messages are being brought into the same polite announcement pattern used by other lists.

### Nested admin work areas

- **Business management:** Suppliers (supplier records, service areas, products/catalogue); Procurement (requests, RFQ sourcing, supplier matching, purchase request, purchase order revision); Transportation (plan, plans, challan); Discount rules; Quote follow-ups; Partner brands (brands and categories); Experts & services (add/directory); Blogs (write/articles); Commissions (record/records); Loyalty (overview/settings); Quotation rules (overview/settings).
- **Sales:** RFQ/enquiry intake and ownership, quotation workflow and editor, quotation comparison/preview/send, quote follow-ups, order details, orders and delivery/dispatch, transport planning, status changes.
- **Catalogue:** product list and editor, variants, category/brand management, product-code and image fields, customer display preview, publish state.
- **Website editor:** home section order/content blocks, category images, navigation, website pages, FAQs, policies, social links, guides, expert directory and blog content.
- **Shared interaction states across areas:** loading skeletons and status announcements, inline alerts/notices, empty result messaging, unsaved-change confirmations, destructive confirmations, dialogs, previews, and upload progress/errors. Dynamic empty-result messages and actual request failures use polite status and assertive alert semantics, respectively, in the audited admin list/workflow views.
- **Shared form control note:** native selects appear in storefront, customer account and admin filters/forms. Base-select arrow alignment is governed by global app styles, with a custom-icon exception for material option editing.
- **Shared dialog behavior:** admin modal roles are covered by `useAdminDialogFocus`, which manages focus entry, Tab containment and return to the trigger; feature workflows still own their close/cancel behavior.

## Shared components and foundations

### Cross-surface search and filter behavior review

List filters apply as their values change; dropdown/status filters do not require a separate Apply or Filter button. Reviewed controls include storefront marketplace brand/category/availability filters, journal topic and professional-directory filters, customer-account quotation search/status/request filters, admin customer/follow-up status, RFQ/procurement status groups, supplier list refinements, recent activity, Audit Log, Notifications, catalogue filters and Operational Reports date range. Paired report dates refresh once both values make a valid range. Search controls that submit text to a remote endpoint (such as supplier directory search) remain explicit searches; they are not filter-apply actions. Storefront catalogue search/navigation submit actions and CSV export likewise remain distinct from filtering.

- **Storefront:** `Header`, `Footer`, `ScrollToTop`, `PageMetadata`, `ProductImage`, `SearchSuggestions`, `FaqSection`, `RequestContactForm`, `MaterialListEditor`, customer auth context, `ProductDetailSurface`.
- **Customer:** `CustomerProtectedRoute`, account shell/navigation, `AccountContent`, `QuotationResponse`, `ClientActionConfirmation`.
- **Admin:** `AdminProtectedRoute`, `AdminWorkspaceLayout`, `GlobalAdminSearch`, `FeatureBoundary`, `confirmAdminAction`, shared admin button/input/table classes, common enum formatting.
- **Visual foundations:** storefront tokens in `apps/web/src/index.css`; admin tokens and shared rules in `apps/admin/src/admin.css`; account-specific tokens in `customer-portal.css`; product detail styles in `packages/storefront-ui/product-detail-surface.css`.
